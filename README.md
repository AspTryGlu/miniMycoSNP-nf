# 🍄 miniMycoSNP

## Overview
miniMycoSNP is a lightweight wrapper designed to run the main MycoSNP workflow sequentially, processing one sample at a time using a simple Bash loop.

This approach is optimized for environments with limited storage capacity, such as single servers or small computational infrastructures.

---

## Motivation
The standard `mycosnp-nf` pipeline is powerful but storage-intensive, especially when processing multiple samples simultaneously.

Typical outputs from a Candida auris run include:

- `work/` directory: tens to hundreds of gigabytes per sample (intermediate files, temporary data, cached processes)
- `results/` directory: several gigabytes per sample, depending on outputs (VCF, alignments, trees, reports)

Because the `work/` directory accumulates large intermediate files across all samples, disk usage can grow rapidly and exceed available storage.

---

## Estimated `work/` directory size (Candida auris)

| Number of samples | Estimated `work/` size |
|------------------|-----------------------|
| 10 samples       | ~ 200 – 500 GB        |
| 50 samples       | ~ 1 – 2.5 TB          |
| 100 samples      | ~ 2 – 5 TB            |

> ⚠️ Note: These values are approximate and can vary depending on sequencing coverage, read length, pipeline configuration, reference genome, and computing environment (e.g., container engine, filesystem, and parallelization settings).

---

## How miniMycoSNP works (and what makes it different)
miniMycoSNP changes the execution model of `mycosnp-nf` to reduce disk usage:

- Runs one sample at a time instead of processing all samples simultaneously  
- Executes only the main MycoSNP workflow (reference-based SNP analysis)  
- Uses a Bash for-loop to iterate through samples  
- After each run:
  - Deletes the `work/` directory (Nextflow temporary files)  
  - Removes intermediate trimmed reads generated by `mycosnp-nf`  
- Proceeds to the next sample with a clean workspace  

This approach prevents accumulation of large temporary files and keeps storage requirements manageable.

---

## Advantages

- Low disk usage  
- Compatible with single servers or low-resource environments  
- Simple and reproducible execution  
- No need for HPC or large storage clusters  

---

## Limitations
miniMycoSNP simplifies execution, therefore:

- Does not support `-resume`  
- Does not support `--add_sra`  
- Does not execute the Pre-MycoSNP workflow  
- Only the main workflow is used  

---

## Requirements

- Bash shell  
- Nextflow compatible with `mycosnp-nf`  
- Container runtime such as Docker or Singularity  
- Access to the `mycosnp-nf` pipeline  

---

## Usage

miniMycoSNP is executed through a Bash script:

```bash
bash miniMycosnp_2.sh
```
### Required inputs

1. `input.csv`
   - Must follow the same format as the `mycosnp-nf` samplesheet  
   - Contains paths to paired-end read files  

2. Reference genome (FASTA)
   - A FASTA file used for reference-based SNP calling  

3. `new_samplesheet.csv`
   - An empty CSV file containing only the header  
   - Used internally to process one sample at a time  

### General workflow

- The script reads the `input.csv`  
- Extracts one sample per iteration  
- Writes it into `new_samplesheet.csv`  
- Runs the main MycoSNP workflow  
- Saves results  
- Cleans:
  - `work/` directory  
  - Trimmed reads  
- Continues with the next sample  

---

## Use case
miniMycoSNP is ideal if you:

- Have limited disk space  
- Want to process samples without accumulating `work/` directories  
- Need a simple sequential execution strategy  
- Are running MycoSNP outside of an HPC environment  

---

## Summary
miniMycoSNP trades off parallelism and flexibility for storage efficiency and simplicity, making large-scale fungal genome analysis feasible on modest infrastructure.
